# TO-DO: Manual Setup Steps — 02/02/2026

Everything below must be done by hand. The codebase is built; these are the configuration and credential steps that can't be automated.

---

## Step 1: Create a Google Cloud Project

1. Go to https://console.cloud.google.com/
2. Click the project dropdown (top-left) → **New Project**
3. Name it `Daily Tasks Tracker`
4. Click **Create**, then select it as your active project

**Verify:** The project name appears in the top-left dropdown.

---

## Step 2: Enable the Google Calendar API

1. In your project, go to **APIs & Services** → **Library** (left sidebar)
2. Search for `Google Calendar API`
3. Click it → click **Enable**

**Verify:** Go to **APIs & Services** → **Enabled APIs**. You should see `Google Calendar API` listed.

---

## Step 3: Configure the OAuth Consent Screen

1. Go to **APIs & Services** → **OAuth consent screen**
2. Choose **External** → click **Create**
3. Fill in:
   - App name: `Daily Tasks Tracker`
   - User support email: your email
   - Developer contact email: your email
4. Click **Save and Continue**
5. On the **Scopes** page, click **Add or Remove Scopes** and add:
   - `https://www.googleapis.com/auth/calendar`
   - `https://www.googleapis.com/auth/userinfo.email`
   - `https://www.googleapis.com/auth/userinfo.profile`
6. Click **Save and Continue**
7. On the **Test users** page, click **Add Users** and enter your Gmail address
8. Click **Save and Continue** → **Back to Dashboard**

**Verify:** Under OAuth consent screen, status shows `Testing` and your email is listed as a test user.

---

## Step 4: Create OAuth 2.0 Credentials

1. Go to **APIs & Services** → **Credentials**
2. Click **Create Credentials** → **OAuth client ID**
3. Application type: **Web application**
4. Name: `Daily Tasks Web Client`
5. Under **Authorized JavaScript origins**, add:
   ```
   http://localhost:3001
   ```
6. Under **Authorized redirect URIs**, add:
   ```
   http://localhost:5002/auth/google/callback
   ```
7. Click **Create**
8. A dialog will show your **Client ID** and **Client Secret** — copy both somewhere safe

**Verify:** Under Credentials, you see `Daily Tasks Web Client` listed as an OAuth 2.0 Client ID.

---

## Step 5: Create the Backend `.env` File

1. Open a terminal in the `backend/` folder
2. Copy the example:
   ```
   cp .env.example .env
   ```
3. Open `backend/.env` and fill in:
   ```
   PORT=5002
   NODE_ENV=development
   GOOGLE_CLIENT_ID=<paste your Client ID here>
   GOOGLE_CLIENT_SECRET=<paste your Client Secret here>
   GOOGLE_REDIRECT_URI=http://localhost:5002/auth/google/callback
   SESSION_SECRET=<generate one, see below>
   FRONTEND_URL=http://localhost:3001
   LOG_LEVEL=debug
   ```
4. Generate a session secret by running this in your terminal:
   ```
   node -e "console.log(require('crypto').randomBytes(32).toString('hex'))"
   ```
   Paste the output as your `SESSION_SECRET` value.

**Verify:** `backend/.env` exists and has no placeholder values left.

---

## Step 6: Create the Frontend `.env` File

1. Open a terminal in the `frontend/` folder
2. Copy the example:
   ```
   cp .env.example .env
   ```
3. Open `frontend/.env` and fill in:
   ```
   VITE_API_URL=http://localhost:5002
   VITE_GOOGLE_CLIENT_ID=<paste the same Client ID from Step 4>
   ```

**Verify:** `frontend/.env` exists. The `VITE_GOOGLE_CLIENT_ID` must match the one in `backend/.env`.

---

## Step 7: Start the Backend

1. Open a terminal in the `backend/` folder
2. Run:
   ```
   npm run dev
   ```
3. You should see:
   ```
   Server running on http://localhost:5002
   ```

**Verify:** Open your browser to `http://localhost:5002/health`. You should see:
```json
{"status":"ok"}
```

---

## Step 8: Start the Frontend

1. Open a **second** terminal in the `frontend/` folder
2. Run:
   ```
   npm run dev
   ```
3. You should see Vite output with:
   ```
   Local: http://localhost:3001/
   ```

**Verify:** Open your browser to `http://localhost:3001`. You should see the login page with "Daily Tasks Tracker" and a "Sign in with Google" button.

---

## Step 9: Test the Login Flow

1. Click **Sign in with Google**
2. A Google popup should appear asking you to choose an account
3. Select your test user account (the one you added in Step 3)
4. Grant calendar permissions when prompted
5. The popup closes and you should be redirected to the calendar view

**Verify:**
- Your name and profile picture appear in the top-right header
- No errors in the browser console (F12 → Console tab)
- No errors in the backend terminal

**If it fails:**
- `Error 401: invalid_client` → Double-check Client ID and Client Secret in `backend/.env`
- `redirect_uri_mismatch` → The redirect URI in Google Cloud must be exactly `http://localhost:5002/auth/google/callback`
- `Access blocked: app not verified` → Make sure your email is added as a test user in Step 3

---

## Step 10: Test Task Creation

1. On the calendar view, click **today's date**
2. The task panel modal should open with 6 empty task slots
3. Type a title in the first task (e.g., "Test task")
4. Check the checkbox next to it
5. Click **Save**

**Verify:**
- The modal closes without errors
- The calendar now shows a colored event on today's date (red = 1/6)
- Open https://calendar.google.com/ in another tab — you should see an event called `Daily Tasks: 1/6` on today's date with a red color

---

## Step 11: Test Color Changes

2. Your saved tasks should load (including "Test task" checked off)
3. Check all 6 checkboxes (give them any titles)
4. Click **Save**

**Verify:**

5. Uncheck 3 tasks and save again

**Verify:**

---

## Step 12: Test Session Persistence

1. Refresh the page (F5)
2. You should still be logged in (no redirect to login page)
3. Click a date — your previously saved tasks should still be there

**Verify:** No re-login required after refresh. Tasks persist.

---

## Step 13: Test Logout

1. Click **Sign out** in the top-right
2. You should be redirected to the login page
3. Try navigating to `http://localhost:3001/` directly

**Verify:** You're redirected back to the login page. The session is destroyed.

## Quick Troubleshooting Reference

| Problem | Fix |
|---|---|
| "Sign in with Google" button does nothing | Check `VITE_GOOGLE_CLIENT_ID` in `frontend/.env` |
| Login popup shows error | Check authorized JS origins includes `http://localhost:3001` |
| Login succeeds but calendar is empty | Backend may not have the right Client Secret — check `backend/.env` |
| `CORS error` in browser console | Make sure `FRONTEND_URL=http://localhost:3001` in `backend/.env` |
| `Calendar API has not been used` | Wait 2-3 minutes after enabling the API in Step 2 |
| Tasks don't save | Check backend terminal for error messages |
| Colors don't match Google Calendar | Clear browser cache and reload |

---

## Done?

If all 13 steps pass, the app is fully working. You can now use it daily — open the app, click the date, fill in your 6 tasks, and check them off as you go. Your Google Calendar will paint itself in colors automatically.
